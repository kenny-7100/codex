# 项目知识维护规则

适用范围：本项目新增的协作、研究、决策资料及项目 Skills。
建立及核实日期：2026-11-14（Asia/Shanghai）。

## 触发与授权

在任务完成或重要阶段结束时检查是否出现：

- 用户明确的稳定偏好，或对协作方式的纠正。
- 已核实且后续可能复用的项目事实、限制、隐藏依赖。
- 有根因证据的排查方法，或经过实际执行验证的重复流程。
- 影响后续任务的重要决定，或已有知识的过时、重复和冲突。

上述内容的项目内文档与 Skill 维护已获用户授权，无需逐项请求保存确认。
用户也已授权这类成果自动 push：主动识别、写入、验证后，形成完整更新即可按根 `AGENTS.md` 的规则提交并推送，无需等待代码变更或另一次指示。
保持原任务优先；只维护相关范围，不借沉淀之名全库重构。
此授权限于项目知识维护及对应 Git 交付，不包含执行 Skill 中其他发布、删除或外部写入动作。

## 路由

| 内容 | 主要位置 |
| --- | --- |
| 整个项目共同遵守的短约束和入口 | 根 `AGENTS.md` |
| 用户明确表达的长期协作偏好 | `working-preferences.md` |
| 机制、架构、版本差异、验证过的研究发现 | `docs/research/` |
| 需要保存理由和取舍的关键决定 | `docs/decisions/` |
| 具有输入、步骤、判断、验证和结束条件的可执行方法 | `.codex/skills/<name>/SKILL.md` |

经验尚不成熟时先写知识页；流程稳定后再提炼 Skill，不为每次任务建立 Skill。
同一知识只保留一个主要来源，其他位置用链接引用。

## 写入流程

1. 检索索引和相关文件，判断是否已有可修订条目。
2. 判断复用价值、证据和范围；临时状态、纯猜测、重复信息无需写入。
3. 修订主要来源，补充必要证据和关联入口；新增页面同步更新对应索引。
4. 检查冲突：当前用户指示优先；新证据推翻旧结论时说明变化及依据。
5. 检查相对链接、命令和事实。新增脚本必须实际运行验证；Skill 校验结构和使用边界。
6. 有实际、完整更新且符合自动 push 条件时提交并推送；无改动不创建空提交，失败不自动重试或修复。
7. 在最终交付中简述有意义的沉淀及路径和推送结果，不必重复所有文档内容。

## 证据、版本与时效

- 研究事实引用具体代码路径、提交、发布版本或官方资料；历史做法标明历史版本。
- 观察事实、推断、建议、待核实项应在措辞上可区分；不要补造来源。
- 新知识页注明适用范围和核实日期；仅排版修改不刷新事实核实日期。
- 插件和仓库版本不匹配时标明，不能只凭同名方法认定完整调用关系。
- 采用稳定、语义明确的文件名，通常为小写英文加连字符；Git 保存编辑历史。
- 需要并列比较的不同发布版本可分文件；普通修订不复制成带时间戳的新页。
- 不默认创建大批空模板或使用逐次追加日志代替知识整理。

## 修订与淘汰

- 优先修订原页；重复内容合并到主要来源并修复引用。
- 无法确认是否仍有效时标明待核实及原因，后续相关任务再检查。
- 已失效的操作步骤从当前指引移除；仍有解释价值的内容转为历史说明。
- 仅在确有必要时归档独立历史页；不要保留相互冲突的多个“当前”入口。
- 不记录凭据、私密数据或无关个人信息；不整段复制聊天和庞大日志。
- 维护约定与用户新指示冲突时，执行新指示并更新约定。
