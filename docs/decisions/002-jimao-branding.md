# 002 Jimao 显示品牌与原扩展身份

状态：当前采用。日期：2026-11-14（Asia/Shanghai）。
范围：`vscode-extension/`，官方 `openai.chatgpt@26.51111.21308` 的个人定制版本。
依据：用户明确选择只使用 Jimao，不与官方扩展共存；仅修改用户可见品牌，内部业务不变。

## 决定

- 用户可见的插件品牌使用 **Jimao**，替换扩展显示名称、命令与视图标题、设置说明、面板标题、界面默认文案与多语言文案中的 Codex 品牌。
- Logo 使用用户桌面 `kbtc.svg` 的图案。源文件副本位于 `vscode-extension/overrides/resources/jimao.svg`，配套 256 × 256 PNG 用于扩展列表；不依赖用户桌面路径构建。
- 保留 `openai.chatgpt` 扩展身份、版本、命令与视图 ID、配置键、协议和原有数据读取位置。安装 Jimao 会替换同身份的官方扩展。
- 历史聊天、用户内容、模型指令、内部名称、技术路径、请求头、来源和许可声明不做品牌替换。
- 继续保留聊天管理与持续恢复等现有定制。本次不改 Rust 引擎。

## 实现与验证入口

扩展声明在 `src/manifest.json` 和 `src/vsixmanifest.xml` 中维护，宿主界面标题在对应宿主片段中维护。
`scripts/branding.mjs` 在构建副本中按语法树定位界面文案与语言字典，保留消息 ID、ICU 参数和用户插值；
对已定位的品牌图形替换为用户 SVG，处理启动画面和扩展详情。生成结果及文案变更清单保留在本机 `reports/branding.json`。
不修改原始参考包，不对运行中的 DOM 或用户内容执行全文替换。

执行 `npm test`、`npm run test:ui`、`npm run smoke`、`npm run check-imports`，再构建归档并执行
`npm run verify -- --allow-changes`。宿主冒烟检查断言显示名、图标和原扩展身份。
保留身份防止因本次改名分离 VS Code 扩展存储；不能将此推断为所有上游与定制引擎行为均已兼容。
启动图标以内嵌 SVG 避免 Webview 相对路径解析失败；登录页 `{appName}` 仅在界面消息的插值处替换，保留共享品牌变量在请求头和业务中的原值。
没有逐一访问全部懒加载界面、外部服务页面或验证全部语言的实际渲染。

2026-11-14 本机只读对照：定制与已安装的官方引擎读取默认 `~/.codex`，均识别现有 API Key，前 100 条非归档会话 ID 集合一致。使用原 CODEX_HOME 的隔离 VS Code 已跳过登录页并显示首次引导，观察到 Jimao 文案及新图标。引导来自隔离 VS Code 的空 globalState，正式替换保留原身份和原 VS Code 数据目录。

隔离测试如果显式设置空 CODEX_HOME，就会预期显示登录页，不能据此判断正式插件的数据兼容性；测试窗口须提前说明并在结束时关闭。

## 后续约束

官方更新可能覆盖此同身份定制版本；当前决定不自动更改用户日常 VS Code 的自动更新设置。
用户若重新要求共存，应重新设计扩展注册身份及共享数据方式，不沿用“只改显示名即可共存”的假设。
