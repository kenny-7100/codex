# 003 Jimao 局域网共享入口与窗口归属

状态：当前采用。日期：2026-11-15（Asia/Shanghai）。
范围：Jimao 家庭局域网浏览器访问第一阶段。
依据：用户明确选择仅展示 Jimao、接受 VS Code 在线依赖，手动开启，支持多个窗口选择，仅图片附件，家庭局域网暂不做浏览器认证，并授权目标模式实施与验收。

## 决定

- 插件自动启动一个脱离启动窗口的轻量共享 Web 入口；用户无需另装服务器或单独执行后台命令。
- 2026-11-15 用户确认改为本次运行全局开启/关闭：任意窗口开启后，同一 CODEX_HOME 下已激活及后续激活的窗口自动登记；任意窗口关闭时全局退出共享。未激活窗口不强制启动插件。浏览器通过同一端口选择窗口，各窗口继续独立管理原有 Codex app-server。
- 全局状态仅在共享进程内保存，最后一个登记窗口离开即清除，不持久化到下次启动。窗口通过串行化的发现与命令协调，避免全局关闭后轮询重新开启；登记带宿主 PID，用于清理已经退出的宿主。
- 不把引擎管理、聊天存储和标签存储迁移到独立服务。关闭某窗口仍结束其插件/引擎生命周期，但不影响其他已接入窗口。
- 最后一个窗口离开后入口自动退出；不承诺脱离 VS Code 运行、电脑关机/休眠或进程崩溃后的任务继续。
- 浏览器复用原 Webview 和宿主 RPC；切换保留各窗口页面，重连重新建立客户端并恢复路由，不自动重发用户消息。
- 第一阶段对浏览器不提供认证，使用家庭局域网 HTTP；内部窗口控制接口仅本机并使用内部凭据。后者不等于浏览器登录。

## 会话链接补充决定（2026-11-15）

用户确认采用简洁路径 `/c/` + 12 位随机编号。编号映射由入口服务持久化，
URL 不携带窗口 ID、工作区路径或会话标题；不采用需要额外分享服务的外部短链接。
入口在创建虚拟 Webview 前解析宿主并验证会话，避免先显示默认窗口再跳转。
原窗口离线时优先同工作区，其次当前/最近激活的已接入窗口；读取失败明确报错，
不打开其他会话。共享入口继续只做路由，不接管引擎或迁移运行中任务。

取舍：短编号需要维护本地映射文件，换取稳定且简洁的 URL；映射随 CODEX_HOME 保存，
删除它会使旧链接失效。链接保留现有局域网可操作权限，不新增只读分享模式或浏览器认证。
实现与验收仍以局域网访问文档为主要来源。

## 理由与取舍

单窗口宿主内直接监听端口最简单，但关闭入口所属窗口会影响所有浏览器连接。
完整 VS Code Web 环境超出用户只展示 Jimao 的需求。
完全独立服务接管引擎可以脱离 VS Code，但需要迁移运行状态和存储，不属于用户最终选择。
当前架构在共享入口可用性与现有插件复用之间取得平衡；未来若要求脱离 VS Code，再评估引擎生命周期迁移。

实现、使用、验证证据和边界的主要来源为 [局域网访问文档](../../vscode-extension/docs/lan-access.md)。
