## 恢复阶段验收层次

1. **参考身份**：`npm run bootstrap` 根据独立保存的 `provenance.json` 验证原始 VSIX SHA-256。
2. **恢复代码**：57 个宿主片段拼接后的规范化 AST 与原宿主一致；12,274 个 Webview JS
   逐个比较规范化 AST。另生成 CSS、HTML，共 12,554 个 Webview 文件。没有恢复失败项。
3. **加载图**：`npm run check-imports` 检查已识别的相对导入目标。55,386 条词法记录包括
   38,897 条字面量导入、6,937 条非字面量动态导入和 9,552 条 `import.meta`。
   由变量计算的动态导入不在静态路径存在检查的证明范围内。
4. **真实宿主**：`npm run smoke -- --probe` 使用独立的 VS Code 数据目录运行扩展测试。
   测试实际激活插件、检查四个主要命令、打开侧栏，并断言插入可编辑源码的探针已经执行。
   测试后恢复探针源码并重建当前定制；结果见本机 `reports/vscode-smoke.json`。
5. **定制链路**：`npm run test:customization` 修改宿主及 Webview runtime，检查生成的覆盖，
   对 VSIX 全条目做差异检查。预期只有两个 JS 内容改变，其余条目内容不变，CRC 全部有效。
6. **基线归档**：`npm run package && npm run verify` 检查全部 15,473 个条目、内容、顺序、
   关键元数据、CRC 和整个文件 SHA-256。基线已经生成与原包字节一致的 VSIX。

基线验证值：


上述 AST 比较忽略位置信息、注释与字面量打印元数据，且只对同种 `&&`、`||`、`??`

CSS/HTML 格式化未建立同等强度的语义证明；默认基线构建使用它们的原始字节。

## 原生程序与归档签名

包内 Codex 程序报告版本 `0.169.0-alpha.11.1`，其 Apple 代码签名在构建副本上通过
`codesign --verify --strict`。构建从 ZIP 恢复 32 个文件的可执行权限；历史参考解压目录
缺少这些权限位，直接复制而不恢复会妨碍本地运行。参考原件没有为此修改。

本次 ZIP 中未遇到需要移除的签名尾部；未修改条目的原始局部记录、中央目录字段和归档
结束记录可完整保留，因此可以达到字节一致。修改条目会重新压缩并清除旧的 data descriptor
标志，修改包不应再被描述为官方原始包或拥有官方 Marketplace 发布身份。

## 证明范围

- 原始 TS/TSX、原始注释、开发时模块边界和官方构建流水线没有恢复；保留发布符号名是有意选择。
- 工程依赖原始 VSIX 中的资源和二进制。没有从 Rust 源码重新编译出相同的原生程序，
  也没有确认当前 checkout 与原生程序的精确源码提交对应关系。
- 真实宿主检查覆盖启动、命令注册、打开侧栏和修改代码的实际执行，没有逐项覆盖登录、
  全部模型交互、语音、远程环境及所有懒加载界面。没有发送真实 Agent 任务作为验收。
- 基线文件完全相同说明没有引入发布包内容差异；实际运行仍取决于 VS Code、账户、网络和服务端。
- 修改 `src/manifest.json` 中版本、发布者、扩展 ID 或 Marketplace 元数据时，还需同步
  `src/vsixmanifest.xml` 根清单。目前提供可编辑原清单，未提供通用的 VSCE 清单生成器。
- 当前定制流程支持新增文件和替换文件；删除原始包条目需要明确扩展打包器，目前缺失
  原始 `extension/` 文件会报错，避免无意漏包。
- 打包器明确拒绝 ZIP64、多磁盘归档和未支持的中央目录尾部，适用当前参考包及正常规模的定制。

运行报告与完整 VS Code 日志留在本机的忽略目录；Git 中只保存必要的结论与复现方法。
