# Jimao 家庭局域网访问

适用：Jimao `openai.chatgpt@26.51111.21308` / Apple Silicon macOS。
核实日期：2026-11-15（Asia/Shanghai）。第一阶段由用户明确选择无浏览器认证、手动开启、仅图片附件。

## 使用

1. 在希望从浏览器访问的 VS Code 工作区窗口中打开命令面板，执行 **Jimao: 开启局域网访问**。
2. 插件启动或复用共享入口，提示本机与局域网地址，并复制一个局域网地址。默认端口为 `8765`。
3. 在同一家庭局域网的浏览器打开该地址，在顶部 **窗口 / 工作区** 中选择已接入窗口。
4. 开启一次后，同一 `CODEX_HOME` 下已激活及之后激活的 Jimao 窗口自动加入，通常约 2–5 秒出现在选择器中。未激活插件的窗口不会被强制启动。名称和工作区路径用于区分窗口；选择器宽度不足时从左侧省略，优先保留路径后缀，随窗口尺寸自动适配，悬停提示及辅助功能名称保留完整路径。顶部栏始终单行，选择器填满剩余宽度，状态文本过长时省略；左右边距统一为 12px。
5. 执行 **Jimao: 复制局域网访问地址** 可再次获取地址；**Jimao: 关闭局域网访问（全部窗口）** 全局关闭，所有窗口退出共享。

端口通过 `chatgpt.lanPort` 配置。同一 Codex 用户目录下的窗口共享同一端口；更改端口前先全局关闭局域网访问并等待共享入口退出。占用端口不会被自动抢占。
有多个网络适配器时，提示可能包含 VPN 或虚拟网络地址，应使用浏览器设备能够访问的家庭网络地址。
没有文件夹的空窗口可登记，但发送消息沿用原插件约束，要求先打开文件夹或工作区。

## 行为

- 浏览器复用原始 Jimao Webview，通过宿主现有消息桥和客户端协调 RPC 访问所属窗口的引擎。
- 右上角齿轮右边的新建按钮在当前浏览器页面打开新聊天；输入后点击右下角发送按钮。浏览器的 `chatgpt.newChat` 命令由所属虚拟 Webview 直接响应，不再发送到桌面侧栏。 刷新或断线恢复时注入的 `initial-route` 只用于恢复页面，不能据此走原插件的独立编辑器新建分支；LAN 页面在 `YV` 中保留浏览器内导航。验收必须覆盖先打开历史聊天、刷新恢复，再点击新聊天，宽屏和窄屏均应回到 `/`，不发送桌面新建面板命令。
- 浏览器聊天详情左上角保留返回按钮，刷新或重连恢复历史聊天后也显示；普通聊天点击后回到包含最近聊天和“查看全部”的首页列表。原插件根据 `initial-route` 隐藏独立聊天返回入口的规则不适用于 LAN 页面；首页不显示返回按钮。
- 支持聊天、实时回答、工具执行与确认、停止、历史搜索、改名和标签；标签继续使用原宿主存储。
- “查看全部”面板宽度受视口约束；手机端筛选纵向排列，打开时不自动聚焦搜索框，避免立即唤起键盘。搜索控件视觉字号统一为 13px，触屏下以 16px 计算字号配合 0.8125 控件缩放保留 iOS 聚焦兼容；输入框视觉高度 32px，排序与刷新/清空按钮统一 28px。小高度下弹框可滚动。
- 聊天管理在 640px 及以下宽度每页 5 条，宽屏每页 10 条；标签外观与名称哈希规则见[聊天管理定制](chat-management.md)。浏览器的本地模式栏取消负边距，与输入框保持 8px 间距，避免边线重叠。
- 移动端固定视口比例，外层页面与聊天 iframe 都禁止网页手势缩放；触屏输入控件使用至少 16px 字号，避免聚焦自动放大，保留正常单指滚动。浏览器或系统强制的无障碍缩放可能覆盖网页限制。
- 窗口切换保留各窗口自己的 iframe、聊天页面和草稿。切换不发送消息、不停止任务。
- 浏览器刷新及实时传输重连后，恢复所选窗口和最近的页面路由，并用新的虚拟 Webview 重新初始化宿主状态；不在同一 RPC 会话中继续使用丢失过消息的客户端，避免能力引用与导出 ID 失效。不会自动重新发送用户消息。
- 浏览器断开不主动停止任务；关闭所属 VS Code 窗口则沿用插件原有引擎退出行为。共享入口不会接管引擎。
- 开启状态只保存在当前共享进程内，不写入持久化开关；最后一个已接入窗口离开后立即清除开启状态，下次启动默认关闭。宿主异常退出还会检查进程存活并通过心跳过期移除。全局关闭不停止引擎任务，仅断开浏览器入口。
- 关闭最先开启入口的窗口不影响其他已接入窗口；最后一个窗口离开后，入口通常约 30 秒退出。异常退出的宿主通过心跳过期移除，时间更长。
- 第一阶段图片支持 PNG、JPEG、WebP、GIF，单张最多 10 MiB，一次最多 16 MiB。浏览器选择器与宿主图片选择桥均用于图片，不承诺一般文件或目录上传。
- 图片通过原宿主链路交给引擎。需要落盘的浏览器图片保存在 Codex 用户目录下的 `jimao-lan/uploads/<窗口ID>/`；不自动删除可能仍被会话引用的文件。
- 设置、差异与计划消息在浏览器当前界面导航。差异页顶部固定保留“← 返回聊天”，内容和错误状态均提供该入口；点击恢复进入前的聊天（重建浏览器虚拟 Webview，不重新发送消息或停止任务）。差异页依赖临时内容，刷新恢复到失效的 `/diff` 路由时退回最近聊天，没有记录则回首页。打开源码、定位编辑器、IDE 上下文等编辑器专属操作仍依赖主机 VS Code。
- 浏览器不提供用户登录或配对。可以连通端口的设备可操作已接入窗口。仅作为用户确认的家庭局域网入口，不配置公网隧道或路由器映射。

## 结构与生命周期

```text
浏览器：窗口选择器 + 每窗口保留的 Jimao iframe
  ↕ HTTP POST / SSE（同源，普通局域网 HTTP）
共享入口进程：网页、资源、窗口登记、消息路由
  ↕ 本机 HTTP 长轮询 / 消息投递
每窗口 Jimao 扩展宿主：虚拟 Webview、原宿主 RPC、图片选择桥
  ↕ 原有 stdio
每窗口原有 Codex app-server
```

入口由插件用 VS Code/Electron 自带运行时的 Node 模式启动，不需要安装系统 Node 或服务器软件。
进程脱离启动窗口，但没有迁移引擎管理权。入口运行代码复制到稳定目录，避免依赖版本化扩展安装目录。
默认目录为 `~/.codex/jimao-lan/`，设置 CODEX_HOME 时使用对应目录：

- `runtime-v2/`：入口代码副本；
- `gateway.json`：端口、协议版本、PID 和内部宿主连接凭据，文件权限 `0600`；不提交；
- `gateway.log`：本机入口日志；
- `uploads/`：按窗口隔离的落盘图片。

内部宿主连接凭据仅用于窗口登记与路由控制，不是浏览器访问认证。内部接口同时限制为本机连接。
静态资源只允许从已登记插件的 Webview 目录读取，检查解析后的真实路径，拒绝越界符号链接。
消息队列、请求体、连接数和慢客户端缓冲设置上限。页面不依赖第三方 Web 服务包。
浏览器不继承 VS Code 注入的主题变量，适配层须提供按钮、下拉、列表悬停/选中及工具栏的背景/前景色；原界面的中性按钮图标使用 `--vscode-dropdown-background`，缺失会导致浅色图标与浅色圆形背景混同。发送与停止状态均检查实际图标颜色并保留停止状态截图。列表悬停采用深灰 `#2a2d2e`，通过真实会话行 hover 后的计算样式与截图验证，避免变量缺失导致高亮透明。
普通局域网 HTTP 下补齐随机 UUID，避免只在 localhost 安全上下文中工作；麦克风、系统剪贴板等浏览器能力不在第一阶段验收范围。

协议版本升级为 2。旧版共享服务不会被自动接管：升级时需先在所有旧窗口关闭共享，等约 30 秒入口退出，重新加载所有参与窗口，再在任意一个窗口开启一次。

## 开发入口

| 路径 | 职责 |
| --- | --- |
| `overrides/out/lan/server.cjs` | 独立共享入口、登记、心跳、事件流、资源路径及退出 |
| `overrides/out/lan/host.cjs` | 启动发现、窗口连接、虚拟 Webview、宿主 RPC 与图片桥 |
| `overrides/out/lan/bridge.js` | 浏览器 acquireVsCodeApi 适配、字节编码、重连与路由保存 |
| `overrides/out/lan/shell.html` | 窗口选择器和各窗口 iframe 生命周期 |
| `src/extension-host/056-activation.js` | 注册命令与释放入口连接 |
| `src/extension-host/051-webview-messaging.js` | 原文件选择服务为浏览器提供替代实现 |
| `overrides/webview/assets/header-92de4b85dd13.js` | 在 LAN 模式报告路由用于刷新恢复，不改变桌面路由 |
